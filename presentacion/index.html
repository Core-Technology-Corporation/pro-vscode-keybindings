01Resumen

El proyecto

El proyecto combina dos capas. La primera es un keymap declarativo, organizado por categoría (editor, terminal, Git, depuración, explorador), que un script de build compila y valida antes de publicar. La segunda es una extensión en TypeScript con 10 comandos propios.

Entre esos comandos están Smart Run, que detecta el tipo de proyecto y lo ejecuta de la forma adecuada; un flujo de commits con Conventional Commits; y dos limpiadores de código, Limpiar consolas y ⚡ Super, que estandarizan el logging y los imports sin cambiar la lógica.

Problema

VS Code trae atajos genéricos, y tareas repetitivas como ejecutar el proyecto, hacer un commit con formato o quitar logs de depuración requieren varios pasos o extensiones separadas.

Objetivo

Reducir esas tareas a una tecla, sin configuración y con el mismo comportamiento en Windows, Linux y macOS.

Público

Desarrolladores JavaScript/TypeScript, React y React Native que usan VS Code y Git a diario.

03Funcionalidades

Qué hace

Smart Run

Ctrl+F12 detecta el tipo de proyecto (React, React Native, Java, HTML, extensión de VS Code) y ofrece cómo ejecutarlo.

Flujo de commits

Menú numerado de Conventional Commits con commit y push (Ctrl+F9), Quick Commit y apertura en GitHub Desktop.

⚡ Super

Elimina logs de depuración, agrega default: a los switch, reagrupa los imports en externos, internos y relativos, y protege los imports de React.

Limpiar consolas

Asegura un console.error en cada catch y es idempotente: borra lo que insertó en la ejecución anterior antes de reinstrumentar.

Keymap validado

El build falla si dos entradas comparten la misma tecla o si un JSON es inválido.

Atajos contextuales

Cláusulas when específicas: Ctrl+F5 ejecuta SQL en archivos .sql y recarga la ventana en el resto.

04Arquitectura

Cómo está construido

src/*.json  (editor, git, debug, terminal, …)
      │  scripts/build.js — valida JSON, campos y teclas duplicadas
      ▼
package.json › contributes.keybindings   +   dist/keybindings.json

extension/extension.ts  (~1.300 líneas)
      │  esbuild → dist/extension.js  (CJS · Node 18 · vscode externo)
      ▼
activación: onStartupFinished → 10 comandos registrados
  • Una sola fuente de verdad genera el manifiesto, porque VS Code solo lee los keybindings desde package.json.
  • La limpieza combina transformaciones propias con editor.action.formatDocument y organizeImports, en lugar de implementar un formateador nuevo.
  • La selección del Explorador, que la API no expone, se obtiene con copyFilePath.

07Ingeniería

Decisiones y próximos pasos

Seguridad

  • No hace llamadas de red: no hay URLs ni llamadas HTTP en el código de la extensión.
  • Sin telemetría, según su política de privacidad.
  • El README advierte que Ctrl+F9 hace push sin confirmación.

Retos técnicos

  • Transformar código fuente sin un parser completo y sin cambiar la lógica.
  • Evitar conflictos con los atajos nativos de VS Code.
  • Leer la selección del Explorador sin una API oficial.

Hoja de ruta

  • Corregir ⚡ Super con JSX multilínea (detectado durante esta documentación).
  • Usar la TypeScript Compiler API o Babel para las transformaciones.
  • Agregar pruebas automatizadas con casos JSX/TSX.
